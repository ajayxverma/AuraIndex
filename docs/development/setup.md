# Development: Local Setup and Operations

## Prerequisites

- macOS or another POSIX environment with Bash-compatible shell utilities.
- Python 3.12 managed by `uv` (ChromaDB compatibility); `uv` must be on PATH.
- Node.js 20+ and npm.
- `lsof` and `curl` for the start/stop scripts.
- An LLM provider API key for answer generation. Default provider is Groq.

## Quick start

From the repository root:

```bash
./run.sh
```

The script creates the backend virtual environment and frontend dependencies if missing, creates `backend/.env` if absent, starts a standalone Chroma server if needed, waits for its heartbeat, then starts FastAPI and Next.js.

Open:

- Frontend: http://localhost:3000
- FastAPI docs: http://localhost:8000/docs
- Health: http://localhost:8000/health
- ChromaDB: http://127.0.0.1:8001

Stop all services started by this project:

```bash
./stop.sh
```

Ctrl+C in the terminal running `./run.sh` also shuts down its process group. The stop script avoids killing a process on one of these ports if its working directory is outside the project.

## Environment configuration

`backend/.env.example` documents the available settings. The first `./run.sh` creates a private `backend/.env` with a random JWT secret; review it and set a valid LLM API key before asking questions.

| Setting | Default | Purpose |
|---|---|---|
| `JWT_SECRET` | Generated by run script | Signs dashboard JWTs. Keep private and at least 32 characters. |
| `JWT_EXPIRE_MINUTES` | `720` | JWT session lifetime. |
| `CORS_ORIGINS` | `http://localhost:3000` | Comma-separated browser origins allowed by FastAPI. |
| `DATA_DIR` | `./data` | SQLite and Chroma data root, relative to backend working directory. |
| `MAX_UPLOAD_MB` | `25` | Per-file upload limit. |
| `CHROMA_MODE` | `server` | `server` uses separate Chroma; `embedded` uses local in-process Chroma. |
| `CHROMA_HOST` / `CHROMA_PORT` | `127.0.0.1` / `8001` | Chroma server address. |
| `EMBEDDING_PROVIDER` | `local` | `local` or `openai` compatible embedding provider. |
| `EMBEDDING_MODEL` | `all-MiniLM-L6-v2` | Model identifier; changing it changes the collection. |
| `EMBEDDING_API_KEY` / `EMBEDDING_BASE_URL` | empty | Independent embedding credentials/endpoint. |
| `LLM_PROVIDER` | `groq` | `groq` or `openai` compatible chat provider. |
| `CHAT_MODEL` | `openai/gpt-oss-120b` | Chat model name. |
| `LLM_API_KEY` / `LLM_BASE_URL` | empty / provider default | Independent chat credentials/endpoint. |
| `CHUNK_SIZE` / `CHUNK_OVERLAP` | `1000` / `200` | Character-based chunking parameters. |
| `TOP_K` | `5` | Number of retrieved chunks for default RAG requests. |

Local embeddings need no API key. The model may be downloaded the first time the local embedding function initializes. Groq provides chat generation here; it is not the embedding provider.

To change provider/model settings, edit `backend/.env` and restart with `./stop.sh` then `./run.sh`. If the embedding provider/model changes, re-index documents so their vectors use the new embedding space.

## Manual development mode

Run commands in separate terminals. When using server mode, start Chroma first:

```bash
cd backend
.venv/bin/chroma run --path ./data/chroma --host 127.0.0.1 --port 8001
```

Backend:

```bash
cd backend
.venv/bin/uvicorn app.main:app --reload --port 8000
```

Frontend:

```bash
cd frontend
npm run dev
```

## Data and backup

- SQLite: `backend/data/app.db`.
- Chroma data: `backend/data/chroma/` in server mode.
- Original uploaded files are not retained.
- Back up both stores together while the services are stopped for a consistent local backup. Restore both to the same `DATA_DIR` and keep the same embedding provider/model configuration.
- Avoid manually editing Chroma's internal files.

## Troubleshooting

### Port already in use

Run `./stop.sh`; then inspect ports 3000, 8000, and 8001 with `lsof -nP -iTCP:<port> -sTCP:LISTEN`. `run.sh` refuses to start on occupied frontend/backend ports and only reuses port 8001 if the Chroma heartbeat responds.

### Health reports Chroma down

In server mode, make sure Chroma is listening at the configured host/port. `./run.sh` starts it before FastAPI. `GET /health` reports Chroma connectivity.

### Login redirects unexpectedly

The browser JWT is stored in localStorage and expires after `JWT_EXPIRE_MINUTES`. Sign in again. Changing `JWT_SECRET` invalidates existing sessions.

### File indexing fails

Check accepted file extension, maximum upload size, whether the document contains extractable text, embedding provider configuration, and Chroma health. Scanned PDFs need OCR, which is not included.

### Provider errors

Check `LLM_PROVIDER`, `CHAT_MODEL`, `LLM_API_KEY`, and (for non-default-compatible endpoints) `LLM_BASE_URL`. Embedding configuration is separate under `EMBEDDING_*`.
